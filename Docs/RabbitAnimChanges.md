# 토끼 v2 애니메이션 수정 기록

사용자가 허락만 하면 되는 수정은 묻지 않고 진행하고, 바뀐 내용을 여기에 모은다(2026-11-19 요청).
각 항목은 **원인 → 결과**, **바꾸기 전 → 후**, **되돌리는 법** 순서로 적는다.

## 2026-11-19

### 1. 공격·피격 중 귀가 툭 바뀌던 문제 (ABP_RabbitV2)
- **원인:** 상체 슬롯(UpperBody)을 섞는 Layered Blend가 Spine1부터 그 위를 전부 덮어서 귀도 같이 덮였다.
- **결과:** 걷다가 공격하거나 맞는 순간, 귀가 출렁이던 자세에서 공격·피격 클립에 구워 둔 귀 자세로 0.05초 만에 바뀌었다.
- **전 → 후:** 상체 블렌드 뒤에 Layered Blend 노드를 하나 더 넣었다. 이 노드가 귀(Ear_L_01, Ear_R_01부터 끝까지)만 공격 전 이동 자세(FullBodyPose 캐시)에서 로컬 공간으로 가져온다. 그래서 머리는 공격 동작을 따르고, 귀는 머리에 붙은 채 걷기·대기 흔들림을 그대로 이어간다.
- **되돌리기:** AnimGraph에서 `AnimGraphNode_LayeredBoneBlend_2`와 그 옆 `Use cached pose 'FullBodyPose'`를 지우고, 첫 Layered Blend 출력을 Local To Component에 다시 연결한다.

### 2. 지루함 상태가 대기 동작을 처음부터 다시 틀던 문제 (ABP_RabbitV2)
- **원인:** 지루함 동작을 지운 뒤 BoredIdle 상태가 8초짜리 Rabbit_Idle을 재생하게 됐다. 그런데 Idle→BoredIdle 전이(입력 없이 10초)는 그대로 남아 있었다.
- **결과:** 10초마다 대기 동작이 처음부터 다시 시작됐다. 그때마다 0.5초(들어갈 때)와 2초(나올 때) 동안 서로 다른 구간의 대기 동작이 섞였고, 그 사이 귀·머리 움직임이 평균이 돼 흐물흐물해졌다.
- **전 → 후:** Idle→BoredIdle 전이 조건 `TimeSinceLastInput >= 10`을 `>= 1000000`으로 바꿔 사실상 걸리지 않게 했다. 상태와 노드는 나중에 새 지루함 동작을 넣을 수 있게 남겨 뒀다.
- **되돌리기:** Locomotion 상태 머신의 Idle→BoredIdle 전이에서 비교값을 10으로 되돌린다.

### 3. 대기 동작의 머리 움직임이 LookAt에 덮이던 문제 (ABP_RabbitV2)
- **원인:** 카메라 방향을 바라보게 하는 LookAt이 머리(Head) 뼈에 걸려 있었고, 대기 중 알파가 1.0이었다. LookAt은 뼈의 정면 방향을 목표 쪽으로 통째로 돌린다.
- **결과:** 대기 동작에 넣은 고개 돌림·힐끗 보기·끄덕임·도리도리가 게임에서는 거의 사라지고 갸웃(좌우 기울기)만 남았다.
- **전 → 후:** LookAt 대상 뼈를 Head에서 Neck으로 옮겼다. 목이 카메라 방향을 바라보고, 머리는 목 위에서 대기 동작의 움직임을 그대로 한다. 목 뼈의 정면 축은 `(0, -0.277, 0.961)`이다. Blender 기준으로 목이 앞으로 16° 숙어 있고 FBX→UE 변환에서 Y가 뒤집혀서 이 값이 된다. Z축만 쓰면 고개가 뒤로 젖혀진다. PIE에서 뒤쪽 카메라로 원래 설정(Head, Z)과 비교해 머리가 똑같이 바로 서 있는 것을 확인했다. 단, 앞쪽에서는 보지 못했다. `set_torso`가 머리 회전의 절반을 목에 주기 때문에, 대기 동작의 고개 움직임은 원래 크기의 약 절반이 보인다.
- **되돌리기:** AnimGraph의 LookAt 노드에서 Bone to Modify를 Head로, LookAt Axis를 (0, 0, 1)로 되돌린다.

### 4. 착지 동작이 안 나오던 문제 (Rabbit_JumpLand, ABP_RabbitV2 Land 상태)
- **원인:** Land 상태의 Apply Additive 노드에서 Additive 입력이 비어 있었다.
- **결과:** 착지할 때 아무 동작도 없었다. 또 Land→Locomotion 자동 전이는 상태 안의 재생 노드가 끝날 때를 기준으로 걸리는데, 재생 노드가 없어서 멈춰 서 있으면 Land 상태에 계속 머물렀다.
- **전 → 후:**
  - Rabbit_JumpLand를 additive로 바꿨다. 로컬 공간이고, 기준 포즈는 Rabbit_Idle 0프레임이다. 이 클립을 참조하는 곳은 없었다.
  - Land→Locomotion 자동 전이가 클립이 0.25초 남았을 때 시작하게 했다(원래는 블렌드 시간 0.4초 기준). 그래서 착지 충격과 다시 일어서는 동작이 끝까지 보인다.
  - Land 상태에 Rabbit_JumpLand 재생 노드(반복 안 함)를 만들어 Additive 입력에 연결하는 일은 MCP로 할 수 없었다. MCP 도구가 상태 안쪽 그래프에 노드를 만들지 못하기 때문이다. 그래서 에디터 재시작 때 `Saved/LevelSource/apply_rabbit_v2_pass3.py`가 처리한다.
- **되돌리기:** Land 상태의 재생 노드를 지우고, 자동 전이의 Automatic Rule Trigger Time을 -1로 되돌린다.

### 5. 공격 오브가 손가락을 튕기기 전에 몸 중앙에서 나가던 문제 (C++ AbilityComponent)
- **원인:** `CastInstantly`가 입력 순간 캐릭터 중심에서 오브를 만들어 바로 쐈다. 공격 동작에서 손가락을 튕기는 건 0.1초다.
- **결과:** 오브가 먼저 날아가고 손가락은 그 뒤에 튕겨서 따로 노는 것처럼 보였다.
- **전 → 후:** `FAbilityData`에 두 값을 추가했다. 기본값은 예전과 같아서 다른 어빌리티는 바뀌지 않는다.
  - `LaunchDelay`(초, 공격속도 배율로 나뉨, 기본 0)
  - `LaunchSocket`(기본 없음)

  BasicAttack은 0.1초 뒤에 `RightHand`에서 나간다. 조준점은 발사 순간 다시 잡는다. MyRabbit 값은 재시작 스크립트가 넣는다.
- **되돌리기:** MyRabbit의 BasicAttack에서 LaunchDelay를 0으로, LaunchSocket을 None으로 바꾼다.

### 6. 이동하면서 공격 (C++ Rabbit, 이전 단계에서 작성, 이번에 빌드)
- `bLockMoveOnAttack`(기본 false)을 추가했다. 이제 공격할 때 멈춰 서지 않는다.
- `AttackAnimation`(Rabbit_Attack)은 상체 슬롯에서 공격속도 배율대로 재생된다.
- BasicAttack의 CastMontage(예전 전신 공격)를 비운다. 남아 있으면 상체 공격 위를 전신 동작이 덮어서 다리가 멈춘다.

### 7. 뛰면서 공격하면 상체가 툭 서고 왼팔이 멈추던 문제 (ABP_RabbitV2)
- **원인:** 상체 슬롯은 Spine1부터 위를 메시 공간에서 통째로 공격 클립으로 바꾼다. 공격 클립은 서 있는 자세에서 만들었다.
- **결과:** 달리기는 상체를 18° 앞으로 숙이고 어깨를 비틀며 팔을 흔든다. 그런데 공격하는 0.6초 동안은 상체가 거의 선 자세(5°)로 0.05초 만에 바뀌고 왼팔도 흔들기를 멈췄다.
- **전 → 후:** 상체 블렌드와 귀 블렌드 사이에 Layered Blend를 하나 더 넣었다(`AnimGraphNode_LayeredBoneBlend_0`). 공격이 섞인 자세 위에, 슬롯 전 이동 자세를 다시 섞는다. 범위는 Spine1부터 위인데 오른팔(RightShoulder, Blend Depth -1)만 뺀다. 섞는 비율은 속도에 따라 `MapRangeClamped(GroundSpeed, 0~300 → 0~0.7)`이다.
  - 서 있을 때: 지금처럼 상체 전체가 공격 동작을 한다(비율 0).
  - 걸을 때: 비율 0.35.
  - 뛸 때: 비율 0.7. 상체 기울기·비틀림과 왼팔 흔들기는 70% 달리기를 따르고, 오른팔만 100% 공격 동작으로 튕긴다.
  - Blend Depth -1이 뼈를 빼는 동작은 UE 소스(`FAnimationRuntime::CreateMaskWeights`, 가중치를 더한 뒤 0~1로 자름)로 확인했다.
- **되돌리기:** `LayeredBoneBlend_0`과 거기 붙은 `Use cached pose 'FullBodyPose'`, `GroundSpeed`, `MapRangeClamped`를 지우고, `LayeredBoneBlend_1` 출력을 `LayeredBoneBlend_2`의 Base Pose에 다시 연결한다.

### 8. 달리기가 걷기의 연장처럼 보이던 문제 (Rabbit_Run_F, 사용자 요청)
- **요청:** "달리기는 걷기의 연장으로 밖에 안 보여. 보폭을 넓게, 팔은 ㄴ자 말고 편하게 휘두르게."
- **원인:**
  - 발이 엉덩이 바로 앞(허벅지 +30°)에 닿고 뒤로도 조금만(허벅지 -21°) 밀고 떨어졌다.
  - 발을 차고 나가자마자 뒤꿈치를 엉덩이 밑으로 접었다.
  - 그래서 두 발이 가장 멀어져도 35cm였고, 초당 5보로 종종거려 걷기와 비슷한 보폭으로 보였다.
  - 팔은 팔꿈치를 85~99°로 굽힌 ㄴ자 그대로 앞뒤로만 움직였다.
- **전 → 후 (`v2/scripts/rabbit2_run.py` 기본값, 옛 값은 파일 주석에 남김):**
  - 한 주기: 12 → 14프레임(초당 5 → 4.3보, 한 걸음 120 → 140cm).
  - 디딜 때 엉덩이를 1.5cm 더 낮춰 다리가 닿는 거리를 늘렸다(디딘 발이 땅에서 미끄러지는 거리 48 → 56cm, 양 끝에서 다리가 다 펴짐).
  - 공중 구간: 위아래 흔들림 3 → 4.5cm.
  - 발을 차고 나간 뒤 뒷다리가 잠깐 뒤에 남았다가(허벅지 -28°) 접힌다. 무릎은 63°까지 끌어올리고(전에는 58°), 디디기 직전 정강이를 앞으로 뻗었다가 끌어당기며 디딘다.
  - 결과: 두 발 사이가 최대 47cm(전에는 35cm).
  - 발 옆 정강이가 뒤로 처지는 구간에서는 발목을 더 젖혔다. 그래서 발끝이 땅에서 1cm 떠 있다(검사 전 -0.5cm).
  - 팔: 팔꿈치 80±8°(ㄴ자) → 뒤에서 약 50°, 앞으로 오면 64~78°까지 자연스럽게 접힌다. 팔을 몸 쪽으로 8° 붙이고, 손은 덜 쥐고(말림 34 → 20) 더 흔들리게 했다.
  - 팔이 몸통을 파고드는지 검사했다. 전 프레임에서 최소 1.1cm 떨어져 있었다(이전 클립에는 -0.7cm 프레임이 있었다).
- **확인:** Blender에서 옆·앞·대각선으로 찍어 확인했다. UE에 다시 가져왔다(`Saved/LevelSource/reimport_rabbit_v2_clips.py`, 길이 0.400 → 0.467초). 게임에서는 아직 못 봤다.
- **되돌리기:** `rabbit_v2_before_run2.blend`로 되돌리거나, `rabbit2_run.py` 주석의 옛 값을 기본값으로 돌린다. 그다음 Run_F를 다시 굽고 내보내서 가져온다.

### 8-1. [되돌림] 달릴 때 다리 간격
- 사용자의 "뛸 때 다리를 좀 더 벌렸으면"을 달리기로 잘못 이해해서 한 수정이다. 실제 요청은 스페이스바 점프였다(10번).
- 같은 날 달리기는 8번 상태(`RUN_W` 7, thigh 키 -28/63)로 되돌렸다. 다시 굽고 내보내서 UE에 넣는다.
- 되돌린 뒤 Blender 수치는 8번과 같다(앞뒤 최대 간격 47.4cm, IK 0.19cm, 발끝 여유 1.06cm).
- 아래는 되돌리기 전의 기록이다.

### 8-1 (되돌리기 전 기록). 달릴 때 다리 간격 (Rabbit_Run_F)
- **원인:**
  - 게임 카메라는 토끼 뒤에 있다.
  - 엉덩이 관절은 몸 중심에서 10~11.6cm 옆인데, 달리기 발목은 7cm에 놓였다. 걷기는 7.8~8.7cm다.
  - 그래서 뒤에서 보면 두 발이 중심선 근처에서 만나 다리가 붙어 보였다.
- **전 → 후:**
  - 좌우: 발목을 한쪽 7cm에서 11cm로 벌렸다(`RUN_W`). 엉덩이 바로 아래에 디딘다.
  - 앞뒤: 조금 더 벌렸다. 공중에서 뒷다리가 -32°까지 뒤에 남고(전에는 -28°), 무릎은 66°까지 올라간다(전에는 63°). 앞뒤 최대 간격은 47.4cm에서 49.4cm가 됐다.
  - IK는 정확히 닿고, 발끝은 땅에서 1cm 위로 떠 있다.
- **확인:** Blender 뒤쪽 시점에서 7cm, 10cm, 11cm+앞뒤를 비교한 뒤 마지막 것을 골랐다. UE에 다시 가져왔다. 게임에서는 아직 못 봤다.
- **되돌리기:** `rabbit_v2_before_run3.blend`로 되돌리거나, `rabbit2_run.py`의 `RUN_W`를 7로 하고 주석의 이전 thigh 키로 되돌린다.
- **추가 (같은 날, 사용자 "좌우 간격을 좀 벌리는게 좋겠어"):**
  - `RUN_W`를 11에서 14.5cm로 바꿨다. 엉덩이 관절보다 약간 바깥을 디딘다.
  - 뒤쪽 시점에서 11, 13, 14.5를 비교했다. 14.5에서 다리 사이 틈이 확실히 보였고, 앞에서 봐도 뒤뚱거리지 않았다. IK 오차는 0.04cm, 발끝은 땅에서 0.96cm 위에 있고, 팔이 몸을 파고드는 곳은 없다.
  - Blender에서 굽고 내보내는 것까지 했다.
  - UE로 가져오는 건 사용자 확인이 필요하다. 에디터를 닫으려 했지만 90초 안에 닫히지 않았다(사용자가 PIE로 테스트 중이었음). 강제로 닫지 않았다.

### 9. 점프가 뻣뻣하고 팔이 벌어져 있던 문제 (Rabbit_JumpStart / JumpLoop / JumpLand, 사용자 요청)
- **요청:** "점프할 때 다리가 너무 고정적이야, 더 역동적으로. 팔은 양쪽으로 벌어진 거 같아, 가슴 쪽으로 모아. 소극적이고 겁 많은 토끼의 점프 느낌."
- **원인:**
  - 공중 자세에서 팔은 균형 잡듯 양옆으로 48° 들려 있었다(손이 몸 중앙에서 35cm 밖).
  - 공중 루프 동안 다리는 ±4~5°만 천천히 흔들렸다.
- **전 → 후 (`v2/scripts/rabbit2_actions.py`, 옛 값은 주석에 남김):**
  - **컨셉:** 점프가 무서운 토끼처럼 몸을 웅크린다.
  - **점프 시작(0.33초):**
    - 차고 오르는 순간에는 다리를 길게 뻗고 팔은 내린다.
    - 이어서 움찔하며 앞발을 가슴 앞으로 끌어올린다. 살짝 높이 올라갔다가 자리를 잡고, 손목은 한 박자 늦게 아래로 늘어진다.
    - 어깨를 움츠리고 고개를 숙인다.
    - 두 무릎을 차례로 확 끌어당긴다(허벅지 62°, 무릎 120~126°까지 넘쳤다가 자리 잡음).
  - **공중 루프(0.8초):**
    - 다리를 번갈아 버둥거린다(한 루프에 두 번). 허벅지 ±9°, 무릎 ±15°이고, 무릎이 허벅지보다 한 박자 늦게 펴져서 발이 작은 원을 그리며 발끝을 턴다.
    - 몸도 발차기에 맞춰 살짝 흔들린다.

- 주우면 화면 오른쪽에 `+1 박쥐 날개`(희귀도 색)가 3.5초 뜸. 같은 아이템은 한 줄에 합쳐짐.

**아이템 13종** (`/Game/Items/DA_Item_*`, 아이콘 `/Game/Items/Icons`)

| 분류 | 아이템 | 효과 |
| --- | --- | --- |
| 소모품 | 체력 물약 / 마나 물약 / 당근 | HP 50 / MP 40 / HP 20 회복. 가득 차 있으면 쓰지 않음 |

| 머리 | 토끼귀 두건 | 방어력 +2, 최대 MP +10 |
| 몸 | 견습 로브 | 체력 +2, 방어력 +2 |
| 신발 | 가벼운 신발(고급) | 이동속도 +6% |
| 장신구 | 달빛 반지(희귀) / 송곳니 목걸이(고급) | 지능 +4·최대 MP +15 / 마력 +2·최대 HP +20 |

- 시작할 때: 체력 물약 3, 마나 물약 2, 당근 5. 견습 마법봉과 견습 로브를 낀 채로 시작.
- 박쥐 드랍(마리마다 줄별로 따로): 날개 55%(1~2개), 송곳니 20%, 체력 물약 15%, 마나 물약 12%, 달빛 가루 5%, 두건·신발·목걸이 각 4%, 반지·지팡이 각 2%. 바닥에 희귀도 색으로 빛나는 구슬로 떨어지고, 2.6m 안에 오면 끌려와 주워짐. 가득 차면 남음.
- 아이콘은 Blender로 만든 간단한 3D 모형을 렌더링했다(`Saved/LevelSource/make_item_icons_blender.py`). 외부 에셋은 쓰지 않았다.

**능력치 연결**
- **원인:** 토끼 마법 피해는 오브에 적힌 값(25)으로 고정이었다.
- **결과:** 마력이 피해에 쓰이지 않아서 무기의 마력 보너스가 의미가 없었다.
- **전 → 후:** 피해 = 오브 피해 × (1 + (마력 − 5) × 5% + 지능 × 2.5%). 기본 능력치(마력 5, 지능 0)는 예전과 같은 1배다. 견습 마법봉을 끼면 1.1배가 되어 피해가 28로 나온다.
- 장비 보너스는 저장되는 기본 능력치와 따로 둔다(`EquipmentBonus*`). 그래서 저장하고 불러와도 두 번 쌓이지 않는다.
- 방어력·최대 HP/MP·공격속도·이동속도도 장비 보너스를 더한다.

**저장:** 세이브와 레벨 이동 상태에 인벤토리 칸과 장비가 들어간다(아이템 에셋 경로로 저장). 이 기능 전에 만든 세이브는 시작 아이템을 그대로 쓴다.

**시험용 콘솔 명령:** `DebugGiveAllItems`(종류마다 1개), `DebugGiveItem MoonRing 1`.

**확인한 것 (점검 봇, 새 게임 프로세스)**
- 시작 아이템 3칸과 장비 2개가 들어갔다. 마력 7(+2), 피해 1.1배, 최대 HP 215(로브 체력 +2 → +15).
- 무기를 빼면 마력이 7에서 5가 되고, 다시 끼면 7로 돌아왔다.
- 체력 물약을 쓰면 HP가 203에서 215로 차고, 물약은 3개에서 2개로 줄었다.
