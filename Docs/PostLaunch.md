| 목표 | 확인 방법 |
| --- | --- |
| 받은 사람이 끝까지 간다 | 클리어 화면까지 가는 비율. 게임 안에 기록 수단이 없어서, STOVE Studio에서 볼 수 있는 지표를 먼저 확인 **(확인 필요)** |
| 막히는 곳을 찾는다 | STOVE 리뷰·커뮤니티 글, 직접 받은 피드백을 [버그 목록](BugList.md) 형식으로 정리 |
| 크래시 0 | 리뷰·문의에 크래시 신고가 오면 그날 확인 |

## 3. 작은 마케팅을 실행해 볼 시점

큰 홍보보다 "개발 과정을 보여 주는 글 + 짧은 플레이 영상"을 3번 올리는 것을 제안합니다. 글감은 이미 문서로 남아 있습니다.

| 시점 | 무엇을 | 소재 |
| --- | --- | --- |
| 5주차 금 11/27 (스토어 자료 확정한 날) | 개발기 1편 + 플레이 GIF | "어깨 뒤 카메라에서 쿼터뷰로 바꾼 이유" ([주간 기록 #3](WeeklyLog/Week03.md)의 결정 후보 → 4주차 적용) |
| 6주차 금 12/4 (심사 신청한 날) | 출시 예정 공지 | 스토어 스크린샷, 한 줄 소개 "쓰러뜨린 적이, 동료가 된다." |
| 8주차 (승인 후) | 출시 공지 + 2분 플레이 영상 | 마일스톤 8주차 산출물과 같이 만듦 |

- **채널:** **(입력)** 예: STOVE 인디 커뮤니티, 개인 개발 블로그, 수강생 커뮤니티
- **잴 것:** 글마다 조회·댓글 수, 스토어 페이지로 넘어간 수(링크에 표시 가능하면)

## 4. 하지 않을 것

- 유료 광고: 데모 단계라 효과를 잴 기준이 없습니다.
- 출시 전 새 기능 약속: 로드맵의 "넣을 때"가 확정되지 않은 것은 공지에 쓰지 않습니다.
