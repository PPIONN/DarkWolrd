# 역할 맵 (1인 개발)

> 게임팀의 역할을 혼자 하는 프로젝트에 옮겨 적은 표입니다. 한 사람이 모든 역할을 맡기 때문에, 역할마다 **언제 그 역할을 하는지**와 **다음 역할로 넘길 때 무엇을 남기는지**를 정해 둡니다.

## 역할과 산출물

| 게임팀 역할 | 내 프로젝트에서 하는 일 | 남기는 것 | 도구 |
| --- | --- | --- | --- |
| PD·기획 | 주간 목표와 범위 결정, 넣을 것·뺄 것 판단 | 주간 기록의 계획, 1페이지 기획서 | Markdown |
| 프로그래머 | C++ 게임플레이, UI, 자동 점검 봇 | 커밋, 코드 주석 | Visual Studio, Claude Code |
| 레벨 디자이너 | 맵 구역 배치, 동선, 난이도 | 구역 좌표, 스크린샷 | 언리얼 에디터 |
| 아티스트 | 메시·애니메이션·재질 교체 | 에셋, [에셋 출처 목록](Assets.md) | Blender, Meshy, Poly Haven |
| 사운드 | 효과음 제작과 연결 | 합성 스크립트, 사운드 에셋 | Python |
| QA | 자동 점검, 외부 플레이테스트 진행 | [플레이테스트 기록](Playtest/), 문제 목록 | 자동 점검 봇 |
| 빌드·릴리스 | 설치본 빌드, 설치 테스트, 배포 | zip, [체인지로그](../CHANGELOG.md) | BuildRelease.ps1 |

AI(Claude Code)는 구현과 점검을 돕는 도구로 씁니다. 범위, 우선순위, 유지·제외 결정은 직접 합니다.

| 요일 | 주 역할 | 하는 일 |
| --- | --- | --- |

| 목 | 프로그래머 → QA | 남은 구현, 저녁에 빌드 스크립트로 중간 설치본과 자동 점검 |
| 금 | QA → 빌드·릴리스 → PD | 외부 플레이테스트, 최종 설치본, 체인지로그, 주간 기록 |

## 역할을 넘길 때의 규칙

혼자라도 역할을 바꿀 때 아래를 남겨야 다음 역할이 기억에 기대지 않고 일할 수 있습니다.

| 넘기는 쪽 → 받는 쪽 | 남길 것 |
| --- | --- |
| 기획 → 프로그래머 | 기능마다 "무엇을 하면 끝인가" 한 줄 (예: 쓰러지면 실패 화면에서 다시 하기를 고를 수 있다) |
| 프로그래머 → QA | 빌드가 되는 커밋, 자동 점검 통과, 바뀐 점을 체인지로그에 한 줄 |
| 아티스트 → 빌드 | 에셋 출처 목록 갱신. 출처·라이선스를 모르는 에셋은 빌드에 넣지 않음 |
| QA → 기획 | 문제 목록에 P0·P1·P2 우선순위와 본 근거(누가, 어디서) |
| 빌드 → 다음 주 기획 | 설치본 링크, 설치 테스트 결과, 못 한 것과 이유 |
